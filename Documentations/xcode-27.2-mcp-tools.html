XcodeListTargets Lists targets in the current Xcode workspace, optionally scoped to a single project. Each entry

Lists targets in the current Xcode workspace, optionally scoped to a single project. Each entry includes the target's name, the project that contains it, its product type (e.g. application, framework, unit-test bundle), and role flags (isTestTarget, supportsHostingTests, isAppExtension, isAggregate). Hidden synthetic blueprints and Swift package products are not listed. Pass the containingProjectPath value back to GetTargetBuildSettings, UpdateTargetBuildSetting, or other target-aware tools to operate on a specific project. Inline results are capped at 100 entries; the complete list is always written to fullTargetListPath in grep-friendly format with keys like TARGET_NAME, CONTAINING_PROJECT, PRODUCT_TYPE_IDENTIFIER, PRODUCT_TYPE_NAME, IS_TEST_TARGET, SUPPORTS_HOSTING_TESTS, IS_APP_EXTENSION, IS_AGGREGATE.

(e.g. 'application', 'framework', 'framework.static', 'library.static', 'bundle.unit-test', 'bundle.ui-testing', 'app-extension', 'extensionkit-extension'). workspaceIdentifier string Identifies the target workspace directly (used in headless mode): its workspace identifier (e.g. workspace1) or its absolute path.

XcodeListTemplates Lists Xcode templates available in this Xcode install. Use this to discover the templateIdentifier

Lists Xcode templates available in this Xcode install. Use this to discover the templateIdentifier and option keys to pass to XcodeNewTarget (kind="target") or XcodeNewProject (kind="project"). The unfiltered listing is large (~200 target templates); always pass at least one filter — typically platformFilter (e.g. ["ios"]) and/or categoryFilter (e.g. ["Application"]). Use nameFilter for a substring search by name. Pass templateIdentifier when you already know the identifier to get back just that one entry. Each TemplateInfo includes the template's options (popup / checkbox / text) so the caller can fill them in without a second round trip — EXCEPT when no filter is supplied: in that "broad browse" case the inline `options` array is empty for each entry to keep the response small. Pass any filter (or templateIdentifier) to get the full option schema. Inline results are capped at 100; the complete list with full options for every template is always written to fullTemplateListPath in grep-friendly format with keys like TEMPLATE_INDEX, TEMPLATE_IDENTIFIER, TEMPLATE_NAME, TEMPLATE_CATEGORY, PLATFORM, IS_MULTI_PLATFORM, OPTION_*. Supports kind="target" (default) and kind="project". Other kinds return an error listing supported values.

templateIdentifier string Optional exact identifier match (e.g. 'com.apple.dt.unit.iosFramework'). When supplied, the listing returns only the matching template — useful for retrieving the option schema for a known template.

XcodeNewProject Creates a new Xcode project from a template. The project is written to disk at the specified directory.

Creates a new Xcode project from a template. The project is written to disk at the specified directory. Use XcodeListTemplates with kind="project" to discover valid templateIdentifier values and their options. Required: templateIdentifier, productName, and destinationPath. Template-specific options go in `options`: each key is an option identifier from XcodeListTemplates (e.g. 'languageChoice', 'coreData', 'sceneLifecycle'). Checkbox options accept 'true'/'false' (also 'YES'/'NO' or '1'/'0', case-insensitive). Popup options must use one of the strings from the OptionInfo.possibleValues list. organizationIdentifier sets the bundle identifier prefix (e.g. 'com.example'). If omitted, the template's default is used. teamIdentifier sets the development team for code signing. If omitted, no team is set. After creation, use XcodeOpenWorkspace to open the generated project.

options object Optional dictionary of template-specific options. Keys are option identifiers from XcodeListTemplates (e.g. 'languageChoice', 'coreData', 'sceneLifecycle'). All values are strings.
